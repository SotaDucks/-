# 剑鱼

按住鼠标左键蓄力，松开后朝指针方向跳跃。右键拖动视角，滚轮缩放，R 重新投放，T 打开手感菜单。

## 互撞与测试鱼

玩家之间由房间服务器统一判定碰撞，并向双方发送相反的冲量。客户端继续计算自己的分段鱼身，因此碰撞会影响移动和旋转，也会打断受到明显撞击的蓄力。高速接触会回查一个发包间隔，撞击消息带有确认序号和投放代次，避免重复施力或把旧撞击施加到重新投放的鱼上。

T 菜单最上方的“随机跳跃测试鱼”默认开启。它会在玩家附近随机蓄力跳跃，使用与联机互撞相同的碰撞算法；关闭后立即移除。开关自动保存在当前浏览器中，不受手感预设影响。测试鱼仅本机可见，可以离线测试。

碰撞使用分段近似形状，并非精确网格碰撞。联机撞击仍受网络延迟影响，不提供精确叠放或完整的服务器物理模拟。

## 本地运行

从仓库根目录启动静态 HTTP 服务，例如执行 `python -m http.server 4173 --bind 127.0.0.1`。需要同时提供 `index.html` 与整个 `shared/` 文件夹，不能直接用文件协议打开页面。

在 `server/` 目录安装现有依赖后，执行 `npm run dev` 启动本地 Worker，默认端口为 8787。打开 [本地测试房间](http://127.0.0.1:4173/?room=test&relay=ws%3A%2F%2F127.0.0.1%3A8787)，用两个页面进入同一房间即可测试真实联机互撞。也可通过“邀请”按钮复制房间链接。

未指定 relay 参数时，页面仍连接原有线上 Worker。联机互撞需要同时更新前端文件与 `server/` Worker；后者沿用现有的 `npm run deploy` 部署流程。新页面连接旧服务器时会提示服务器需更新，并保留旧版位置同步。旧版客户端仍可进入新版房间，但不参与互撞。

## 验证

在根目录执行 `node --test tests/*.test.mjs`，验证物理响应、高速接触、测试鱼跳跃、消息确认、重新投放隔离、过期快照和休眠恢复。

本地 Worker 启动后，执行 `node tests/network-check.mjs`，验证两个真实 WebSocket 客户端交换姿态、接收同一次撞击并在离开时清理玩家。
